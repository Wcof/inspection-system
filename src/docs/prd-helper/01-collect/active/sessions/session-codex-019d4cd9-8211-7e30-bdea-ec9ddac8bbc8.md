## 2. 业务目标

系统最终要让机器人明确以下三件事：

1. 应该怎么走
2. 走到哪些巡检点
3. 到达每个巡检点后，需要检查哪些设施设备，以及每个设施设备对应的云台坐标和识别图片

在此基础上，系统还需要支持为机器人配置周期性巡检计划，并由计划定时生成任务，驱动机器人自动执行。

## 3. 核心业务流程

### 3.1 一次构图

1. 机器人在目标区域运行一遍，完成地图构建
2. 系统保存地图、机器人轨迹、定位参考数据
3. 系统自动或半自动生成大量途径点
4. 运维人员维护途径点类型并连接途径点生成路径网络
5. 在路径网络上规划巡检路线并标记巡检点

产出：

- 地图
- 途径点集合
- 途径点连线形成的路径网络
- 可用导航区域
- 初始巡检路线
- 巡检点基础位置

### 3.2 途径点与路径网络

1. 地图构建后生成多个途径点（Waypoint）
2. 每个途径点配置类型和属性
3. 通过连接多个途径点生成可行路径
4. 一条巡检路线本质上是路径网络中的一个有序子路径

途径点类型建议至少包含：

- 巡查点
- 充电点
- 停车点
- 普通通过点

说明：

- 巡查点用于业务巡检停靠
- 充电点用于低电量回充策略
- 停车点用于任务完成后驻停
- 普通通过点用于导航转折，不承载业务检测

### 3.3 巡检点标记

1. 在地图上标记巡检点
2. 为巡检点配置名称、编号、位置、顺序、停留时长等信息
3. 巡检点可以归属到某条巡检路线中

说明：

- 巡检点是“机器人到达并停留的地点”
- 巡检点不是设施设备本身
- 一个巡检点下可以关联多个设施设备
- 巡检点通常来源于“巡查点类型”的途径点子集

### 3.4 二次校对

1. 机器人按照既定路线再跑第二次
2. 在每个巡检点进行精定位校对
3. 校对巡检点的实际到达位置、朝向、停靠姿态
4. 在该巡检点下逐一维护需要检查的设施设备

二次校对阶段的关键动作：

- 机器人停到巡检点
- 操作云台对准某个设施设备
- 记录该设施设备对应的云台 X/Y 坐标
- 拍摄参考图片或上传标准图片
- 保存为该巡检点下该设施设备的识别基准数据

### 3.5 设施设备维护

每个巡检点下可配置多个设施设备，每个设施设备至少维护以下信息：

- 设备名称
- 设备类型
- 设备编码
- 所属巡检点
- 云台 X 坐标
- 云台 Y 坐标
- 参考图片
- 检测项

说明：

- 云台坐标用于机器人到点后快速转向目标
- 图片数据用于视觉识别、模板比对或 AI 检测
- 检测项用于定义设备需要检查什么，例如指针、数值、开关状态、液位、温度显示等

### 3.6 计划与任务

1. 管理员选择机器人
2. 选择该机器人要执行的巡检路线
3. 选择路线中实际要执行的巡检点，或默认执行整条路线
4. 配置计划周期，可按周或按月执行
5. 系统按计划定时生成任务
6. 到达任务执行时间后，系统调度机器人执行

任务执行过程：

1. 机器人按路线前往各巡检点
2. 到达巡检点后按顺序检查设施设备
3. 云台转到预设 X/Y 坐标
4. 采集实时图片
5. 进行识别与判定
6. 记录结果、异常、图片与时间
7. 全部完成后生成巡检记录和任务结果

## 4. 核心对象关系

系统建议按以下层级建模：

```text
机器人
  └── 巡检计划
        └── 巡检任务
              └── 巡检路线
                    └── 途径点网络
                          └── 巡检点（途径点子集）
                                └── 设施设备
                                      └── 检测项 / 识别模板 / 云台坐标
```

补充说明：

- 地图是路线和巡检点的空间基础
- 地图中的途径点和连线定义“可怎么走”
- 路线定义“最终选择怎么走”
- 巡检点定义“在哪里停”
- 设施设备定义“停下后看什么”
- 计划定义“什么时候执行”
- 任务定义“某一次实际执行实例”

3. 生成途径点集合

1. 机器人二次运行，逐点校对

5. 为设施设备配置检测项
6. 巡检点完成校准并投入使用

### 6.3 任务执行时的机器人动作流程

1. 调度器生成任务
2. 任务到时后下发给指定机器人
3. 机器人加载路线和巡检点列表
4. 到达某个巡检点

6. 依次读取该巡检点下的设施设备
7. 云台转动到设备预置 X/Y 坐标
8. 采集图片
9. 执行识别
10. 输出检查结果
11. 写入任务结果
12. 继续下一个设施设备
13. 当前巡检点完成后前往下一个巡检点
14. 全部巡检点完成后任务结束

原文写了“二次校对”，但没有明确校对后到底沉淀什么数据。

1. 先选路线
2. 再决定是否裁剪其中部分巡检点

### 7.7 任务需要保存执行快照

任务生成后，建议保存一份执行快照，而不是执行时完全读取实时配置。

任务快照至少包括：

- 当时的路线
- 当时的巡检点列表
- 当时的设施设备列表
- 当时的云台坐标
- 当时的参考图片版本
