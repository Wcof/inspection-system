# 冲突点

## conflict_001 — 实时平台 vs 双系统
**冲突描述**: 早期方案中存在"实时平台+管理端"的双系统定义，后用户明确改为"管理端+实施平台"，但驾驶舱（实时运行监控）的定位在两套体系中未完全厘清。

- **双方观点**:
  - 早期方案：实时平台负责运行态监控，管理端负责业务管理
  - 当前方案：驾驶舱作为独立项目（drive-dashboard），与双系统并列存在
- **涉及来源**: session-codex-019d673f Turn 7 vs session-codex-019e3dfb Turn 2
- **影响范围**: 系统架构顶层设计
- **决策人**: 用户
- **状态**: partially_resolved
- **结论**: 用户已明确本轮只做管理端+实施平台，驾驶舱独立；但三者之间的数据互通和跳转关系待确认

## conflict_002 — 检测项配置一致性
**冲突描述**: 设备设施采集向导中的检测项配置与检测对象弹窗在字段和交互上曾不一致，经过多次迭代才统一。

- **双方观点**:
  - 采集向导：最初独立实现检测项配置表格
  - 检测对象：独立弹窗实现
  - 用户要求：两者必须完全一致
- **涉及来源**: session-codex-019d65be Turn 11, Turn 13
- **影响范围**: FacilityDeviceForm.vue, MetricManagement.vue
- **决策人**: 用户
- **状态**: resolved
- **结论**: 已统一为同一套字段和行内编辑交互

## conflict_003 — 调度规则布局风格
**冲突描述**: 调度规则配置页面的布局风格经历了多次反复：从分块布局 → 两排平铺 → Ant Design 风格 → 单行列表式表单。

- **双方观点**:
  - 首次尝试：分块布局，被用户认为"按块调整"不够完整
  - 第二次尝试：两排平铺，被用户认为"太丑了"
  - 第三次尝试：恢复 Ant Design 交互（开关控制显示隐藏）
  - 最终方案：单行列表式表单，启用状态控制显示，底部操作区始终显示
- **涉及来源**: session-codex-019e0b90 Turn 28-35
- **影响范围**: DispatchRuleConfig.vue
- **决策人**: 用户
- **状态**: resolved
- **结论**: 最终采用单行列表式表单 + 启用状态控制 + 始终显示底部操作区

## conflict_004 — 校准记录展示策略
**冲突描述**: 校准记录应该完整展示还是简化展示存在分歧。

- **双方观点**:
  - 完整展示：校准记录列表应展示所有历史记录
  - 简化展示：业务层只看最新一条，复杂记录后台存储
- **涉及来源**: session-codex-019d65be Turn 3
- **影响范围**: 校准记录页面、点位管理
- **决策人**: 用户（会议明确）
- **状态**: resolved
- **结论**: 采用简化策略，校准记录菜单隐藏，页面保留待以后使用

## conflict_005 — 巡检点创建页与详情页字段不一致

- **涉及来源**: session-codex-019e25ad Turn 7
- **影响范围**: InspectionPointCreate.vue, InspectionPointDetail.vue
- **决策人**: 用户
- **状态**: resolved
