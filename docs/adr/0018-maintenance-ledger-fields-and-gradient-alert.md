# ADR 0018 — 组件维保台账补追踪字段+到期梯度弹窗，不建树

**状态**：已确认
**日期**：2026-06-23
**关联模块**：7月迭代 模块五（资产管理与维保迁移 — 模块化维保台账）

## 背景

清单模块五要求"重构机器人详情页挂载组件台账。严格按底盘行走组件、感知传感器模块、多目云台、防爆电源管理、无线通信网卡划分为结构化 Tab 分类。数据化追踪记录激光雷达运行小时数、底盘行走轴摩擦力、底盘防爆密封圈密封寿命倒计时，提供到期周期梯度弹出框"。

现状：机器人详情页已有 6 类挂载组件 Tab（底盘/传感器/云台/电源/通信/其他，与清单一致）和结构化维保管理区块（含维保项/周期/状态/下次触发时间 mock 数据）。缺口是数据化追踪字段和到期梯度弹窗。

项目定位为原型系统，所有数据 mock。

## 决策

**改造重点为补数据化追踪字段+到期梯度弹窗，维保项保持扁平不建树**。

"原子动作树"理解为已有的"Tab 分类→维保项"两层组织，不额外建树。

**挂载组件新增追踪字段**（按组件类型差异化，mock）：

| 组件类型 | 追踪字段（mock） |
|---|---|
| 底盘 | 行走轴摩擦力、防爆密封圈寿命倒计时 |
| 传感器 | 激光雷达运行小时数 |
| 云台 | 旋转次数、电机寿命倒计时 |
| 电源 | 电池循环次数、容量衰减率 |
| 通信 | 信号强度趋势、重连次数 |

**到期梯度弹窗**：按剩余寿命百分比分级弹出：
- 30% 预警（黄色）
- 10% urgent（橙色）
- 0% 过期（红色）

**mock 方式**：追踪字段值 mock 生成，到期梯度弹窗在用户访问机器人详情页时按 mock 值判定是否弹出。

## 理由

- 现状 Tab 分类已是"组件→维保项"两层，与清单"原子动作树"层级基本对齐，强行再加一层"子部件"增加配置负担无实际收益
- 真正缺口是数据化追踪字段和到期梯度弹窗，这是用户能感知到的价值
- 原型系统数据全 mock，树结构是过度设计，7 月迭代不值得
- 维保项保持扁平与现状 mock 数据结构兼容，改造成本低

## 后果

- 机器人详情页的挂载组件 Tab 表格新增追踪字段列
- 新增到期梯度弹窗组件（按剩余寿命百分比分级）
- 挂载组件对象新增追踪字段（按组件类型差异化）
- Mock 数据补追踪字段值

## 相关

- 取决于：无（现状已有 Tab 和维保管理基础）
- 影响：机器人详情页展示扩展、挂载组件对象字段扩展
