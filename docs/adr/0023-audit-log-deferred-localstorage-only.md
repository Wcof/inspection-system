# ADR 0023 — 操作审计日志与大屏联动延后，本次只留接口位

**状态**：已确认
**日期**：2026-06-23
**关联模块**：7月迭代 模块一（首页大屏与控制闭环，不在本项目迭代）+ 模块二/五多处引用

## 背景

模块一"首页大屏与控制闭环"包含"关键操作审计沉淀（AuditLog）"功能项，要求消警/确认/终止/控制权抢占等关键操作强制弹出表单写入审计记录（操作人/时间/对象ID/前后值/原因），mock 阶段写入 localStorage 专用 Key。

模块一不在本项目 7 月迭代范围（由新项目承接）。但 ADR 0007（抢占后强制审计留痕）、ADR 0008（终止任务审计留痕）、ADR 0019（接管迁移记录留痕）均引用"与模块一操作审计日志打通"，形成空引用。

项目定位为原型系统，所有数据 mock。

## 决策

**操作审计日志与大屏联动延后，本次只留接口位不做实现**。

- ADR 0007/0008/0019 中"写入审计日志"的落点改为**localStorage 专用 Key（audit-log）的简单追加记录**，不上独立审计页面
- 审计记录字段保持清单口径：操作人/时间/对象ID/前后值/原因
- 不建独立审计日志查看页（模块一范围）
- 后续模块一在新项目落地时，通过迁移 localStorage 审计数据对接

## 理由

- 模块一不在本次迭代，强行建审计页面会越界
- 关键操作的留痕不能完全不做——抢占/终止/接管是安全相关操作，必须有记录可查
- localStorage 追加记录是最轻量的留痕方式，不增加页面复杂度
- 接口位预留（audit-log Key + 字段口径），未来对接模块一成本低

## 后果

- MockService 新增 audit-log localStorage Key 和追加写入方法
- ADR 0007 抢占动作、ADR 0008 终止任务、ADR 0019 接管迁移，均写入 audit-log
- 不建独立审计日志查看页，调试时可通过浏览器 DevTools 查看 localStorage
- 后续模块一落地时迁移审计数据

## 相关

- 取决于：无
- 影响：修订 ADR 0007/0008/0019 的"与模块一操作审计日志打通"表述为"写入 localStorage audit-log"
