# ADR 0010 — 机会事件重新定义为路过隐患告警

**状态**：已确认
**日期**：2026-06-23
**关联模块**：7月迭代 模块二（调度引擎与任务中心 — 机会事件监听与调度响应）

## 背景

清单模块二"机会事件监听与调度响应"原文举了两例：
1. 识别到动火等特种作业审批生效（实为作业票，ADR 0009 已覆盖）
2. 自由巡检中角度优化新看清某阀门 → 弹"建议路径优化"或"主动监护任务"

用户澄清领域语义：**并非所有部件都纳入巡检**。主观上所有部件都该巡，客观上不能全覆盖。机器人路过时新看清一个部件，**不等于要把该部件纳入巡检**。只有当该部件**呈现风险隐患**时才告警；无隐患则静默路过。

此澄清颠覆了清单原文"新看清阀门即触发调度建议"的设计——新看清部件本身不构成事件，只有发现隐患才构成告警。

## 决策

**机会事件重新定义为"路过时新发现隐患 → 告警"**：
- 机器人路过非巡检部件时，若识别到风险隐患（温升/泄漏/堆积物等）→ 触发告警，走现有异常处置流程
- 若无隐患 → 静默路过，不产生任何调度动作
- **砍掉清单原文的"建议路径优化"和"主动监护任务"两类调度动作**
- 不新增调度抢占路径（ADR 0007 中"机会事件人工确认抢占"的分支随之取消）

## 理由

- 符合现场实际：巡检范围是取舍结果，非全量覆盖；路过无隐患部件是常态，不该触发调度动作
- 清单"建议路径优化"是过度设计，会把正常路过变成频繁弹窗打扰操作员
- 与现有异常处置流程天然衔接，无需新增调度链路
- 简化模块二，减少与模块三自由巡检的耦合

## 后果

- 机会事件不作为独立调度触发源，降维为异常处置流程的一个触发场景
- ADR 0007 抢占分级授权需修订：机会事件不再走"人工确认抢占"分支，抢占仅保留"紧急到场/作业票监护自动抢占"一类
- 模块二"机会事件"功能项实际工作量缩减为：在自由巡检模式下，路过时识别到隐患即生成告警（依赖模块三自由巡检落地）
- 模块三自由巡检的"漫游异常即时锚点"与本决策天然对齐（行进中发现温升/气味变动即时锚定）

## 相关

- 取决于：模块三自由巡检落地（路过识别能力）
- 影响：修订 ADR 0007（抢占分级移除机会事件分支）、模块二工作量缩减
