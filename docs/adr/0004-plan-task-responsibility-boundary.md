# ADR 0004 — 计划与任务的职责边界

**状态**：已确认
**日期**：2026-06-23
**关联模块**：7月迭代 模块二（调度引擎与任务中心）

## 背景

清单模块二要求"执行规划解耦，去除硬绑定的执行机器人字段，规划只定路线和检测范围；引入双轨调度策略（自动派车/手动指派）"。

现状计划对象有"执行机器人"必填字段，与"只定路线和检测范围"的目标冲突。计划对象已埋点"业务场景""风险等级""关联规则"字段但未在 UI 启用。

## 决策

计划只管"做什么"（路线 + 检测范围 + 业务场景 + 风险等级），不管"谁来做"。机器人下沉到任务。引入双轨调度（自动派车/手动指派）。

## 理由

- 计划绑机器人会与"动态抢占式 DAG"冲突——抢占时该给哪台车由调度引擎统一裁决，不能回头看各计划的局部绑定
- 已埋点的业务场景/风险等级/关联规则字段正是为解耦而埋，7月启用顺理成章

## 后果

- 计划页的"执行机器人"字段改为可选或移除
- 计划页已埋点的"业务场景""风险等级""关联规则"字段启用到 UI
- 计划派生任务时，机器人由调度引擎按调度规则决定（见 ADR 0005/0006）

## 相关
