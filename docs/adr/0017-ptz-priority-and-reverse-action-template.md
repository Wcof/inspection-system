# ADR 0017 — 云台优先自动判断、倒车动作树固定模板挂路段

**状态**：已确认
**日期**：2026-06-23
**关联模块**：7月迭代 模块四（运行策略与路网底座 — 停车动作优化/云台优先及倒车动作树）

## 背景

清单模块四要求"优化巡检点执行轨迹。若通过旋转云台即可覆盖目标，则不调转车身；高危/封闭狭窄路段直接配置倒车行驶策略，减少掉头与反复调整的无效动作"。

现状：导航点已有停车约束字段——是否倒车/是否掉头/是否窄路/是否有坡道。但"云台优先"逻辑不存在（现状是到点即停车检查，无"用云台旋转替代调转车身"判断）；"倒车"是布尔字段不是动作树。

## 决策

**云台优先是执行端自动逻辑，不配**：到巡检点后，执行端按已有采集姿态字段（ptzYaw/ptzPitch）+ 目标位置几何计算，能覆盖就不调车身，不能才调。无需用户配置。

**倒车动作树挂路段，固定模板不让自定义**：路段新增"倒车动作模板"字段，枚举固定几个模板供用户选：

| 模板 | 说明 |
|---|---|
| 直行通过 | 不倒车不掉头，直接开过去 |
| 减速通过 | 减速但不停车 |
| 停车检查后直行 | 停车→云台扫描→直行离开 |
| 倒车通过 | 减速→打灯→倒车→停车→云台扫描 |
| 掉头再进 | 到点→掉头→反向驶入→停车→云台扫描 |

**路段现状的"是否倒车/是否掉头"布尔字段迁移为模板枚举**（删除布尔字段，避免两套字段冲突）。迁移时按现状布尔值映射到对应模板（如 reverseRequired=true→"倒车通过"，turnAroundRequired=true→"掉头再进"，均为 false→"直行通过"）。

## 理由

- 云台优先本质是几何计算（已有 ptzYaw/ptzPitch + 目标位置），执行端自动判断即可，让用户配反而是负担
- 倒车动作树挂路段与 ADR 0012/0014/0015 一致，所有执行策略归路段
- 固定模板不让自定义：动作序列是安全相关流程，自定义有风险；固定模板经过验证更可靠；5 个模板覆盖典型场景足够
- 迁移布尔字段为模板枚举避免两套字段打架

## 后果

- 路网管理页的路段编辑新增"倒车动作模板"枚举字段（5 选 1）
- 导航点的"是否倒车/是否掉头"布尔字段迁移为引用路段模板（或保留作只读派生展示）
- 执行端 mock：到巡检点时按采集姿态自动判断云台覆盖；行经路段时按模板执行动作序列
- 调度台展示机器人当前动作状态（直行/减速/停车/倒车/掉头）

## 相关

- 影响：导航点停车约束字段迁移、调度台展示扩展
