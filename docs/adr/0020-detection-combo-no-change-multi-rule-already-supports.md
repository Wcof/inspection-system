# ADR 0020 — 检测项组合算法不改，巡检对象多规则关联天然支持

**状态**：已确认
**日期**：2026-06-23
**关联模块**：7月迭代 模块六（AI智能平台对接 — 自训练与大模型识别组合配置）

## 背景

清单模块六要求"改造检测项配置页，支持将检测项能力配置为组合形态（如'自训练读取仪表 + AI多模态判断周围渗漏'），前端封装统一合并名称标识，不让用户重复枚举单算法"。

现状：检测项的视觉映射有 `recognitionMode: 'template'|'ocr'|'ai'` 三选一单算法。巡检对象与检测规则是一对多关系——一个巡检对象可关联多个检测规则。

## 决策

**检测项配置不做调整**。现状数据模型已天然支持"组合形态"——巡检对象关联多个检测规则，每个规则独立配置单算法。

组合场景的实现方式：
- 分别创建"仪表读取"规则（自训练算法）和"渗漏判断"规则（AI多模态算法）
- 将两个规则关联到同一个巡检对象
- 即等于清单所说的"组合形态"，无需改检测项配置

## 理由

- 检测规则每个都是单独的，巡检对象→检测规则是一对多关系，组合通过关联关系天然实现
- 清单作者未察觉现状数据模型已支持组合，"改造检测项配置"是误判
- 改 recognitionMode 为多选会破坏现有单算法规则的简洁性，且无实际收益
- 不引入"合并名称"字段——巡检对象下挂多个规则，展示时按规则各自展示即可，无需合并名

## 后果

- 检测项配置页不做改造
- 模块六第一条工作量降为零
- 后续若用户反馈"多规则展示分散需合并视图"，再考虑展示层封装，不改数据模型

## 相关

- 取决于：无（现状数据模型已支持）
- 影响：模块六工作量缩减
