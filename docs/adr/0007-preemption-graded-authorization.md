# ADR 0007 — 抢占触发权分级授权

**状态**：已确认
**日期**：2026-06-23
**关联模块**：7月迭代 模块二（调度引擎与任务中心）

## 背景

清单模块二要建"动态抢占式 DAG"，要求作业票/机会事件能"强插挂起日常巡检"。但历史会话纪要明确写过"自动调度不得抢占已有执行权，临时调度变更执行权必须人工确认"。两条规则直接冲突。

现状抢占实现：调度台创建紧急任务时硬编码"中断当前任务=是、立即出发=是、优先级=应急"，只覆盖人工紧急一种场景，无 DAG、无自动抢占、无挂起/恢复机制。

任务状态枚举有待执行/执行中/已完成/已暂停/已取消/失败，**缺"已终止"状态**（清单"终止任务审计化"要补的）。

## 决策

抢占触发权**分级授权**：
- **紧急到场 / 作业票监护**：自动抢占，无需人工确认，调度引擎按 DAG 优先级强插挂起当前任务
- ~~机会事件：产出"抢占建议"弹窗，操作员确认后才抢占~~（**已修订见下方**）
- **抢占后强制弹审计表单留痕**，写入 localStorage audit-log（模块一操作审计日志页面不在本次迭代，见 ADR 0023）

**修订（ADR 0010）**：机会事件经领域语义澄清后重新定义为"路过时新发现隐患 → 告警，走异常处置流程"，不再触发调度抢占。抢占分级简化为**单一分支**：紧急到场/作业票监护自动抢占，抢占后强制审计留痕。

## 理由

- 紧急/作业票场景时效要求高，人工确认延误响应
- 机会事件非紧急，自动抢占会打断正常巡检节奏，需人工把关
- 分级授权兼顾时效与可控性，化解历史纪要"人工确认"与清单"强插挂起"的冲突——把"人工确认"范围收窄到非紧急场景
- 强制审计表单与模块一操作审计日志打通，形成留痕闭环

## 后果

- 调度引擎需实现 DAG 优先级排队与挂起/恢复机制
- 任务状态机补"已终止"状态（见后续 ADR）
- 业务场景字段驱动抢占策略分支：紧急到场/作业票监护→自动抢占，其他→人工确认
- 抢占动作触发审计表单弹窗，记录操作人/时间/对象/前后值/原因
