# ADR 0011 — 监护作业人员核对完整 mock 闭环

**状态**：已确认
**日期**：2026-06-23
**关联模块**：7月迭代 模块二（调度引擎与任务中心 — 监护作业人员核对）

## 背景

清单模块二要求"机器人进入特种作业监护区后，开启现场人员人脸/安全帽/行为识别，比对作业票填报的人员身份信息"。

现状：人脸/安全帽/行为识别在 `src/` 零实现，作业票 mock 方案见 ADR 0009。项目定位为原型系统。

## 决策

**做完整比对闭环 mock**：

1. **作业票 mock 数据含"允许作业人员名单"字段**，与作业票本体一起从第三方系统模拟页动态推送（不写死）
2. **第三方系统模拟页加"推送现场人员识别结果"按钮**，mock 识别结果包含：
   - 现场识别到的人员（人脸/安全帽/行为）
   - 每人是否在作业票允许名单内
   - 是否戴安全帽
   - 行为是否合规（如是否有动火作业行为）
3. **比对不匹配即生成告警**，走异常处置流程（与 ADR 0010 机会事件告警同链路）
4. **监护任务详情页加"现场人员核对"区块**，展示名单、识别结果、比对状态

## 理由

- 与 ADR 0009 作业票模拟页思路一致——识别结果用按钮 mock 推送，不需要真 AI
- 完整闭环能演示"作业票开票→机器人到场→识别现场人员→比对不匹配→告警"全链路，对产品验证价值最大
- 只展示不判定是半成品，演示时讲不清闭环；完全跳过会让模块二少一个演示场景

## 后果

- 作业票 mock 数据结构新增"允许作业人员名单"字段
- 第三方系统模拟页新增"推送现场人员识别结果"按钮
- 监护任务详情页新增"现场人员核对"区块
- 比对不匹配走异常处置流程（联动 ADR 0010）

## 相关

- 取决于：ADR 0009（作业票模拟页与 mock 数据结构）
- 影响：异常处置流程新增"人员核对不匹配"告警类型、监护任务详情页新增区块
