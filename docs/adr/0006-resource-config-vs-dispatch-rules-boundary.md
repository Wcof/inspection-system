# ADR 0006 — 资源基础配置页与调度规则配置页的职责边界

**状态**：已确认
**日期**：2026-06-23
**关联模块**：7月迭代 模块二（调度引擎与任务中心）

## 背景

选车规则归属调度规则配置页（ADR 0005）后，需确定与资源基础配置页的边界。现状：
- 资源基础配置页已有"区域→优先指派机器人"配置，独立存 localStorage，页面提示"本区域无空闲时跨区域调度其他空闲机器人"
- 调度规则配置页清单要加"疲劳段频次与优先级控制"

若不划清边界，"区域→优先机器人"配置归属会扯皮。

## 决策

两页一静一动、一资源侧一任务侧：
- **资源基础配置页**升格为"调度资源池"配置：区域→优先机器人（已落地）+ 机器人禁用时段 + 机型兼容白名单（后两项待补）
- **调度规则配置页**只管"任务侧"策略：时间段频次/优先级升格/抢占规则

两页通过区域 ID 关联。调度引擎算派车时先查资源基础配置拿候选机器人，再用调度规则页的时间段策略排序。

## 理由

- 产品意图本就把资源基础配置页当"资源侧底座"用（已有"优先指派机器人"）
- 资源配置变化频率低、调度策略变化频率高，分页更合理
- 强行合并会让调度规则配置页过载

## 后果

- 资源基础配置页补"机器人禁用时段""机型兼容白名单"
- 资源基础配置页的"区域→优先机器人"配置与调度规则页通过区域 ID 关联打通（不再独立存）
- 调度引擎派车流程：资源基础配置拿候选池 → 调度规则页策略排序 → 选定机器人

## 已确认补充

"优先指派机器人"为**软偏好**：配置的机器人是"候选池"，调度引擎在候选池内按就近+电量+负载排序选一台；候选池全没空才溢出到外区域空闲机器人。清单外车在候选池有空时不会主动接本区任务，但可在池空时被调度引擎溢出调用。

**理由**：现状页面提示文案已写"本区域无空闲时跨区域调度其他空闲机器人"，语义就是溢出兜底而非准入锁定；硬绑定会让多机器人场景下 DAG 频繁卡死，与"动态抢占式 DAG"目标冲突。

## 相关

- 取决于：ADR 0005（选车规则归属）
- 影响：调度引擎派车排序算法需实现"候选池内就近+电量+负载排序 → 池空溢出"两段式逻辑
