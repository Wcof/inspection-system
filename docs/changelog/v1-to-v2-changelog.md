## 一、侧边栏菜单变化

**原来**：左侧菜单最下面是「系统配置」栏目（位于实施端）。

**现在**：「系统配置」下方新增了一个 **「系统设置」栏目**，里面包含：

| 菜单项 | 路径 | 说明 |
|---|---|---|
| 第三方系统模拟 | `/management/system/third-party-simulator` | 模拟外部系统向本系统推送数据 |

## 二、任务列表页面变化

**涉及页面**：临时任务列表（TemporaryTaskList）

### 2.1 任务状态从 6 种扩展到 8 种

**原来**：

| 状态 | 颜色 | 显示文字 |
|---|---|---|
| pending | 灰色 | 待执行 |
| running | 蓝色 | 执行中 |
| completed | 绿色 | 已完成 |
| paused | 橙色 | 已暂停 |
| cancelled | 灰色 | 已取消 |
| failed | 红色 | 失败 |

**现在**：新增「待处理」「已终止」两个状态：

| 状态 | 颜色 | 显示文字 | 说明 |
|---|---|---|---|
| pending | 灰色 | 待执行 | — |
| running | 蓝色 | 执行中 | — |
| completed | 绿色 | 已完成 | — |
| paused | 橙色 | 已暂停 | — |
| **processing** | **青色** | **待处理** | **任务执行到某个环节需要人工介入** |
| cancelled | 灰色 | 已取消 | — |
| **terminated** | **红色** | **已终止** | **任务被调度员强制终止** |
| failed | 红色 | 失败 | — |

### 2.2 「删除」功能已废弃

**原来**：点击删除按钮会从系统中物理删除任务数据。

**现在**：**删除功能已停止使用**（点击不再起效）。请改用「终止任务」功能：

- 终止后任务状态变为「已终止」
- 系统会自动记录一条审计日志：谁、什么时间、终止了哪个任务

> 💡 为什么取消删除？任务数据涉及安全追溯，一旦执行就应永久保留，不可物理删除。

## 三、新建/编辑任务时的新字段

**涉及页面**：创建任务表单（task form）

**原来**：只需要填名称、编号、机器人、类型、巡检点。

**现在**：新增以下可选字段：

### 3.1 任务来源（taskSource）

| 可选值 | 中文含义 | 使用场景 |
|---|---|---|
| `execution_plan` | 执行计划 | 由巡检计划自动生成的任务 |
| `dispatch_insert` | 调度插单 | 调度员临时插入的任务 |
| `auto_recheck` | 自动补检 | 系统自动发起的补检任务 |
| `work_ticket` | 作业票 | 由作业票系统推送的任务 |
| `third_party` | 第三方 | 第三方系统创建的任务 |
| `emergency` | 应急 | 应急场景创建的任务 |
| `manual`（默认） | 手动 | 人工手动创建 |

### 3.2 业务场景（businessScene）

| 可选值 | 中文含义 |
|---|---|
| `daily_inspection` | 日常巡检 |
| `hazard_screening` | 隐患筛查 |
| `environment_check` | 环境监察 |
| `operation_guard` | 作业监护 |
| `work_ticket_guard` | 作业票监护 |
| `emergency_arrival` | 应急快速到场 |

### 3.3 优先级（priorityLevel）

| 可选值 | 中文含义 |
|---|---|
| `normal` | 普通 |
| `high` | 高 |
| `emergency` | 紧急 |

### 3.4 风险等级（riskLevel）

| 可选值 | 中文含义 | 说明 |
|---|---|---|
| `normal` | 普通 | 正常作业 |
| `warning` | 警告 | 轻度风险 |
| `alarm` | 报警 | 中度风险 |
| `critical_alarm` | 严重报警 | 高度风险 |
| `hazard` | 危险 | 高度危险 |
| `major_hazard` | 重大危险 | 最高等级危险 |

### 3.5 关联计划（planId）

可选字段，如果这个任务是由某个计划生成的，在这里关联计划编号。

## 四、巡检计划页面变化

### 4.1 机器人改为可选

**原来**：创建计划时必须指定一个机器人（必填项）。
**现在**：**机器人变为可选项**。

- 不填机器人 → 计划只是一个任务模板，执行时由系统自动派车
- 填写机器人 → 和原来一样，指定特定机器人执行

### 4.2 新增字段

| 新字段 | 可选值 | 说明 |
|---|---|---|
| **业务场景** | 日常巡检、隐患筛查、环境监察、作业监护、作业票监护、应急到场 | 标注计划的业务用途 |
| **风险等级** | 普通、警告、报警、严重报警、危险、重大危险 | 标注计划的风险级别 |
| **关联规则** | 可关联一条或多条调度规则编号 | 计划执行时使用哪些调度规则 |

## 五、路段配置页面变化

> **路段**：地图上的一段道路，标识机器人可以通行的路径。

### 5.1 运行策略（新增 2 项）

| 新字段 | 格式 | 说明 |
|---|---|---|
| **心跳间隔** | 100~10000 毫秒 | 机器人在该路段上每隔多久发一次"在线"信号。不填则使用机器人自己的默认值。 |
| **语音提醒** | 下拉选择 | 机器人走到该路段时是否自动播放语音提示：无、前方危险、窄路注意、进入限制区、自定义内容 |

### 5.2 看门狗防护（新增）

| 新字段 | 可选值 | 说明 |
|---|---|---|
| **看门狗触发动作** | 减速、紧急停止 | 如果机器人超过 0.35 秒无响应，触发哪种保护动作 |

### 5.3 倒车方式升级（2 个勾选框 → 5 种固定模板）

**原来**：两个勾选框：「允许倒车」「允许掉头」，组合出 4 种情况。

**现在**：改为一个下拉菜单，5 种固定模板：

| 模板 | 含义 |
|---|---|
| 直行通过 | 不倒车、不掉头，直接通行 |
| 减速通过 | 减速慢速通过 |
| 停止后直行 | 先停车确认后再直行 |
| 倒车通过 | 倒车方式通过 |
| 掉头再进 | 掉头后重新进入 |

> 💡 改为固定模板后，逻辑更清晰，避免组合混乱。

### 5.4 云台扫描配置（新增 8 项完整配置）

> **云台**：机器人的摄像头支架，可以上下左右转动。

| 新字段 | 格式/可选值 | 说明 |
|---|---|---|
| 启用扫描 | 开/关 | 是否在该路段启用云台扫描 |
| 扫描模式 | 连续扫描、来回扫描、固定角度 | 云台的运动方式 |
| 水平起始角度 | 0~360° | 扫描的水平起始位置 |
| 水平结束角度 | 0~360° | 扫描的水平结束位置 |
| 俯仰最小角度 | -90°~+30° | 云台垂直向下/向上的最低角度 |
| 俯仰最大角度 | -90°~+30° | 云台垂直向下/向上的最高角度 |
| 扫描速度 | 5~60 °/秒 | 云台转动的速度 |
| 扫描高度 | 0.5~3.0 米 | 云台安装高度 |
| 危险点标记 | 是/否 | 该区域是否标记为危险点 |
| 危险类型 | 泄漏、温升、杂物、安全行为、气体 | 可多选，标注该路段需要重点检测的危险类别 |

### 5.5 安全等级（新增）

| 可选值 | 含义 |
|---|---|
| 普通 | 正常路段 |
| 警告 | 需要留意安全的路段 |
| 危险 | 安全风险较高的路段 |

## 六、导航点名称统一

**原来**：系统中同时存在两套名字：

- **途径点**（Waypoint）— 旧名称
- **导航点**（NavigationPoint）— 新名称

两套概念并存，容易混淆。

**现在**：
- 统一使用「**导航点**」作为标准名称
- 「途径点」相关功能已标记为 **已废弃**
- 如果系统中还有地方显示"途径点"，它背后其实已经自动切换到导航点数据了，对使用没有影响

## 七、新建页面：第三方系统模拟器

**位置**：侧边栏 → **系统设置** → **第三方系统模拟**

**这是一个全新的页面**，用于模拟外部系统向本系统推送数据，方便测试和演示。

### 页面功能

#### ① 作业票推送

| 按钮 | 说明 |
|---|---|
| **推送作业票** | 模拟作业票系统向本系统推送一张检修作业票 |

点击后系统会：
1. 生成一张虚拟作业票（含名称、允许人员名单、时间信息）
2. 将数据存入系统
3. 在页面显示"已推送"提示

#### ② 人员识别推送

| 按钮 | 说明 |
|---|---|
| **推送现场人员识别结果** | 模拟人员识别系统发送识别到的人员名单 |

点击后系统会模拟一份现场识别到的人员名单。

#### ③ 事件日志

页面底部有一个事件日志列表，每次推送都会记录一条日志，显示推送时间、推送内容。

**典型使用流程**：

```
Step 1: 点击「推送作业票」→ 系统记录作业票
Step 2: 点击「推送现场人员识别结果」→ 系统记录识别到的人员
Step 3: 系统内部可以比对作业票允许人员 vs 实际识别人员
```

## 八、后台新增功能预览

> 以下功能的后台逻辑已开发完成，但前端的操作页面还在后续开发中。目前通过程序接口可以直接调用。

### 8.1 派车引擎（自动选机器人）

创建任务后，系统会自动派车：
1. **先查资源池偏好** — 看该区域有没有偏好机器人列表
2. **按条件筛选** — 从偏好列表中选在线 + 电量充足（> 20%）的机器人
3. **降级兜底** — 如果偏好机器人都不在线，选任意一个可用机器人

### 8.2 任务抢占

紧急场景下（如应急到场、作业票监护），系统可以自动暂停当前正在执行的任务，把机器人调给紧急任务。抢占时会自动记录审计日志。

### 8.3 审计日志系统

以下操作会自动记录审计日志：

| 操作类型 | 日志记录内容 |
|---|---|
| 终止任务 | 记录操作人、原状态→已终止、原因 |
| 抢占任务 | 记录原状态→已暂停、被哪个场景抢占、原因 |
| 远程校准机器人 | 记录哪台机器人、校准了什么部件 |
| 机器人故障接管 | 记录从哪台机器人到哪台机器人、原因 |

### 8.4 远程一键零位校准

后台支持远程校准机器人的云台/机械臂零位。校准后自动记录审计日志。

### 8.5 大模型检测兜底

当主算法识别失败时，可以开启大模型来兜底识别。开启后：
- 主算法成功 → 使用主算法结果
- 主算法失败 + 大模型开启 → 使用大模型结果（备注会显示"大模型增强"）
- 大模型关闭 → 返回无结果

### 8.6 故障接管 / 续巡

机器人在执行任务中故障或低电量时，另一台机器人可以从断点位置继续执行，系统会：
1. 生成一个续巡任务
2. 记录审计日志（谁接管了谁、什么原因）

### 8.7 设备维保寿命监控

系统可以根据设备组件剩余寿命百分比自动判断：

| 剩余寿命 | 级别 | 颜色 | 建议操作 |
|---|---|---|---|
| ≥ 30% | 正常 | 绿色 | 无需处理 |
| 10%~30% | 预警 | 黄色 | 安排保养 |
| 2%~10% | 紧急 | 橙色 | 尽快更换 |
| ≤ 2% | 过期 | 红色 | 立即更换 |

### 8.8 AI 智库（知识库 + 问答）

后台已支持：
- **知识库文件管理**：上传/删除文档（如安全规程 PDF）
- **问答会话**：创建/删除 AI 对话会话
- **聊天消息**：保存用户提问和 AI 回答
- **载体字段**：记录对话发生在哪个设备（PC/手机）、哪个机器人上

### 8.9 作业票人员核对

系统可以比对作业票上允许进入的人员名单与实际识别到的人员：
- 全部匹配 → 通过 ✅
- 人员缺失（允许的人员不在现场）→ 告警
- 身份不明（现场识别到的人不在作业票上）→ 告警

### 8.10 边巡边检执行流

巡检执行过程中，系统后台支持：
- **抽帧识别流**：模拟每秒钟 24 帧的实时画面检测
- **漫游异常锚点**：巡逻过程中发现异常时，自动记录异常位置
- **云台避空保护留痕**：云台转动遇到空旷区域时，自动记录保护日志

## 附录二：8 种任务状态说明

```
                     ┌──────────┐
                     │  待执行   │
                     └────┬─────┘
                          │ 开始执行
                          ▼
                     ┌──────────┐
            ┌────────│  执行中   │────────┐
            │        └──────────┘        │
            │                            │
            ▼                            ▼
     ┌──────────┐                 ┌──────────┐
     │  已暂停   │                 │  待处理   │
     └────┬─────┘                 └────┬─────┘
          │ 恢复                         │ 恢复
          ▼                              ▼
     ┌──────────┐                 ┌──────────┐
     │  执行中   │                 │  执行中   │
     └──────────┘                 └──────────┘

             正常结束 ──→ 已完成
             用户取消 ──→ 已取消
             强制终止 ──→ 已终止
             执行失败 ──→ 失败
```

> **说明**：已暂停、已取消、已终止的区别
> - **已暂停**：可以恢复执行的中断
> - **已取消**：用户主动取消，不可恢复
> - **已终止**：调度员强制终止，不可恢复（替代了原来的"删除"功能）
