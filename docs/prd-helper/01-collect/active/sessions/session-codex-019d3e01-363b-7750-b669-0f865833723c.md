### Agent Answer

根据会议记录，当前 `dashboard` 需要调整的内容可以归纳为以下几类，核心不是“再加几个卡片”，而是把首页真正做成“领导看价值、领班看执行”的多机器人巡检大屏。

**1. 首页主视角要强化“多机器人同时巡检”**
领导第一眼最想看到的是：
- 现在有几台机器人在同时运行
- 这些机器人分别在什么位置
- 正在沿哪条路线运动
- 当前靠近哪个巡检点或处于哪段边巡边检区域

对应调整：
- 地图必须更突出多机器人同时运动的状态
- 必须支持 `1/2/3/全选` 这类机器人快速切换
- 必须有 `全选` 视角
- 多机器人视角和单机器人视角要能快速切换
- 机器人点位、路线、当前所在点位要动态变化，不是静态标记

**2. 首页要突出“领导看汇总价值”**
领导更关心的是汇总结果，不是单个业务细节：

重点展示：
- 全年 / 累计巡检时长
- 巡检效率提升
- 发现问题总量
- 高频问题区域
- 风险等级分布
- 经常出问题的点位或区域

对应调整：
- 增加汇总型指标区
- 增加高频异常区域 / 热点区域表达
- 要有“区域风险升高”的结构化展示
- 不是只展示单点异常，而是展示哪里经常出问题

**3. 多机器人与单机器人要形成两层视角**
会议里反复强调一个问题：  
大屏需要同时支持：
- 多机器人总览视角
- 单机器人深入视角

对应调整：
- 总览层：多机器人位置、运行状态、任务分布
- 单机层：点击某台机器人后，显示：
  - 当前巡检任务
  - 当前巡检点
  - 当前传感器数据
  - 当前可见光 / 红外
  - 当前视觉检测结果
- 页面架构必须清晰回答：
  - 多台机器人时看什么
  - 切到一台机器人时看什么

**4. 巡检任务是核心主线，不是附属信息**
会议明确了：机器人产生的核心价值，本质上是：
- 巡检任务执行
- 巡检任务报告
- 巡检异常发现
- 巡检历史趋势

对应调整：
- 首页所有信息都要围绕巡检任务组织
- 每台机器人必须绑定其当前任务
- 巡检任务要关联：
  - 机器人
  - 路线
  - 巡检点
  - 边巡边检区间
- 任务切换后，地图、点位、路线、证据区、底部执行流都要同步切换

**5. 环境检测要区分“当前点实时数据”和“下个点历史数据”**
会议确认了一个很关键的逻辑：

如果机器人：
- 已到当前巡检点：显示当前点最新实时数据
- 正在前往下一个巡检点：显示下一个巡检点的上一次历史数据，并明确提示“最新数据等待采集”

对应调整：
- `环境检测` 必须跟任务和巡检点联动
- 不能一直显示固定环境数据
- 路途中状态要明确区分：
  - 当前不是实时数据
  - 是下一个点的历史数据预览
- 页面文案要明确标注：
  - `（上次历史数据，最新数据等待采集）`

**6. 巡检点与边巡边检必须区分**
会议明确：
- 定点巡检 和 边巡边检 是两类不同巡检任务
- 边巡边检不是一个点，而是一段动态区域
- 两者阈值和检测逻辑不同

对应调整：
- 页面要明确区分：
  - 定点巡检
  - 边巡边检
- 环境检测和结果展示都要体现这个差异
- 巡检类型展示里必须能看到：
  - 点位型任务
  - 区间型任务
- 边巡边检产生的数据也要被记录、保存、可分析

**7. 巡检告警必须做历史对比，不是只报当前异常**
会议对“异常有意义”这件事说得很明确：
真正有意义的是同一个点位的周期性对比，而不是随便看某次结果。

对应调整：
- 每条巡检告警必须关联：
  - 巡检任务
  - 巡检点
  - 机器人
  - 设备
- 必须展示：
  - 上一次巡检时间
  - 上一次巡检结果
  - 当前结果
  - 差异变化
- 差异表达要具体：
  - 温度上升多少
  - 指标波动几次
  - 从正常转异常
- 要支持按同一点位拉出历史变化趋势

**8. 异常和高风险区域要做“热点化”表达**
会议提到一个明确方向：
如果某些点位 1、2、3 次反复出问题，它就应该逐步变成高危区域。

对应调整：
- 地图上要增加高危区域 / 热点区域表达
- 高频异常区域要可视化
- 风险不是只看静态预设等级，还要叠加巡检实际发现结果
- 可做动态升温 / 加深颜色 / 风险抬升表达

**9. 底部执行流要更业务化**
会议里提到：
不仅要知道时间轴，还要知道机器人现在在哪、从哪到哪、异常后怎么走。

对应调整：
- 底部不是抽象时间轴
- 必须明确展示：
  - 当前机器人所在点位
  - 从哪个点位前往哪个点位
  - 异常后动作：
    - 返回
    - 绕路
    - 继续前进
- 还要支持查看同一点位的历史周期变化

**10. 单机器人弹出信息要更有价值**
点击单机器人后，不是简单看一个名字，而是应该看到关键信息弹层：

建议包含：
- 机器人基本信息
- 当前巡检任务
- 当前巡检单位 / 点位信息
- 当前传感器数据
- 当前可见光 / 红外成像
- 当前异常或检测结果摘要

**11. 后续要预留更智能的交互能力**
会议虽然说这是后续阶段，但首页设计最好留出结构空间：
- 语音控制
- 语音问答 / RAG
- 机器人主动汇报任务结果
- 异常语音播报

这部分现在不用做重，但首页结构别把后续扩展空间堵死。

**一句话总结**
这次 dashboard 需要从“单机器人 + 静态卡片 + 常规大屏”升级成：

`多机器人总览 + 单机器人深入 + 巡检任务主线 + 历史对比 + 风险热点 + 环境检测动态上下文`
