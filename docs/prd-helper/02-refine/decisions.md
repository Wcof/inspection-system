# 设计决策记录

## decision_001：Hash路由方案

- 决策内容：路由方案选择 Hash 路由（createWebHashHistory）
- 决策原因：避免 GitHub Pages 深链接刷新 404 问题，部署稳定性优先
- 替代方案：HTML5 History 模式
- 为什么不选替代方案：GitHub Pages 不支持服务端路由重写
- 影响范围：全局路由
- 来源材料：session-codex-019d674e
- 来源位置：部署方案讨论
- 状态：已确认

## decision_002：Dashboard独立部署

- 决策内容：Dashboard 独立为单独项目，与主 Vue 应用分离部署
- 决策原因：两个系统独立迭代、独立部署，互不影响
- 替代方案：合并到同一项目
- 为什么不选替代方案：技术栈不同（vanilla JS vs Vue），合并增加复杂度
- 影响范围：Dashboard、CI/CD
- 来源材料：session-codex-019d674e
- 来源位置：项目架构讨论
- 状态：已确认

## decision_003：去除独立巡检路线CRUD

- 决策内容：去除独立的"巡检路线"CRUD，巡检路线由巡检计划自动生成
- 决策原因：实际业务中不需要单独管理路线，计划制定后系统自动返回路线
- 替代方案：独立巡检路线管理页面
- 为什么不选替代方案：增加不必要的配置复杂度
- 影响范围：巡检计划、路线管理
- 来源材料：session-codex-019d4cd9 (Turn 3)
- 来源位置：巡检计划讨论
- 状态：已确认

## decision_004：去除独立巡检点层改用巡检设施

- 决策内容：去除独立的"巡检点"业务层，改用"巡检设施"作为聚合层
- 决策原因：巡检点概念与地图执行点混淆，改为巡检设施→停车点→巡检对象→检测规则更清晰
- 替代方案：保留独立巡检点层
- 为什么不选替代方案：概念边界不清，数据模型混乱
- 影响范围：点位管理、设施设备管理、巡检计划
- 来源材料：session-codex-019d673f (Turn 72)
- 来源位置：业务模型讨论
- 状态：已确认

## decision_005：检测项配置为标准能力库

- 决策内容：检测项配置定位为"标准检测能力库"，不绑定具体设施实例；具体绑定通过"对象检测配置"中间层完成
- 决策原因：避免规则库变脏，提高检测能力的复用性
- 替代方案：检测项直接绑定到设施
- 为什么不选替代方案：无法复用，配置冗余
- 影响范围：检测对象、设施设备管理
- 来源材料：session-codex-019d673f (Turn 44, 59)
- 来源位置：检测项配置讨论
- 状态：已确认

## decision_006：检测项配置去除默认采集要求

- 决策内容：检测项配置页去除默认采集要求（采集方向、采集距离、要求说明）和算法能力配置，只保留基础分类、适用对象、结果定义
- 决策原因：实际检测时姿态和图片由大模型处理，算法能力写死使用默认大模型
- 替代方案：保留完整采集要求配置
- 为什么不选替代方案：当前阶段不需要，增加配置复杂度
- 影响范围：检测项配置页
- 来源材料：session-codex-019d673f (Turn 52)
- 来源位置：检测项配置讨论
- 状态：已确认

## decision_007：结果定义按检测类别动态切换

- 决策内容：结果定义根据检测类别动态切换表单：视觉类偏结果状态，热成像偏温度/阈值，气体检测偏浓度/单位/阈值
- 决策原因：不同检测类别的结果定义字段差异大，不能用统一固定表
- 替代方案：统一固定表单
- 为什么不选替代方案：无法适配不同检测类型的需求
- 影响范围：检测项配置、检测结果
- 来源材料：session-codex-019d673f (Turn 53)
- 来源位置：检测结果讨论
- 状态：已确认

## decision_008：连接对象Source/Sink模式

- 决策内容：连接对象配置采用Source/Sink模式：Source固定为当前设施巡检对象，Sink支持选择本设施或其他设施的巡检对象
- 决策原因：连接对象不光连接自身巡检对象，还可能连接其他设备的巡检对象
- 替代方案：Source/Target双端选择
- 为什么不选替代方案：操作复杂度高，容易出错
- 影响范围：设施设备管理
- 来源材料：session-codex-019d673f (Turn 62)
- 来源位置：连接对象讨论
- 状态：已确认

## decision_009：计划不直接选检测项

- 决策内容：计划不直接选择检测项，计划只选巡检范围（巡检设施）；任务生成时从对象检测配置自动展开检测动作
- 决策原因：避免计划里重复配置检测项、漏选、与设备配置冲突
- 替代方案：计划直接关联检测项
- 为什么不选替代方案：配置冗余，容易不一致
- 影响范围：巡检计划、任务生成
- 来源材料：session-codex-019d673f (Turn 44, 59)
- 来源位置：巡检计划讨论
- 状态：已确认

## decision_010：总调度台去除半自动模式

- 决策内容：总调度台去除半自动模式，只保留自动和人工两种调度模式
- 决策原因：简化调度逻辑，差异明确：人工模式需在待确认任务中确认，自动模式自动确认
- 替代方案：保留自动/半自动/人工三种模式
- 为什么不选替代方案：半自动模式逻辑不清晰
- 影响范围：总调度台
- 来源材料：session-codex-019d4cd9 (Turn 31)
- 来源位置：调度模式讨论
- 状态：已确认

## decision_011：Dashboard安全风险颜色策略

- 决策内容：Dashboard 首页安全风险颜色策略：正常状态不用红色，仅异常时用红/橙
- 决策原因：谨慎使用红色，避免领导看到满屏红色产生误判
- 替代方案：正常状态也用绿色/红色区分
- 为什么不选替代方案：领导视角下红色过多造成焦虑
- 影响范围：Dashboard
- 来源材料：session-codex-019d60b4
- 来源位置：Dashboard设计讨论
- 状态：已确认

## decision_012：巡检告警按需弹出

- 决策内容：巡检告警面板改为按需弹出（点击告警点时才显示），而非常驻屏幕
- 决策原因：告警信息量大，常驻屏幕影响其他信息展示，按需弹出更聚焦
- 替代方案：告警面板常驻屏幕
- 为什么不选替代方案：占用屏幕空间过大
- 影响范围：Dashboard
- 来源材料：session-codex-019d4cfe
- 来源位置：Dashboard交互讨论
- 状态：已确认

## decision_014：区域巡检点改为画框选区

- 来源材料：session-codex-019d65be

## decision_015：检测周期下沉到检测项维度

- 决策内容：检测周期和检查窗口下沉到检测项维度（而非设备维度）
- 决策原因：配置粒度应为检测项维度，定义"该检测项多久检+什么时候能检"
- 替代方案：检测周期在设备维度配置
- 为什么不选替代方案：粒度太粗，无法满足不同检测项的不同周期需求
- 影响范围：检测对象、巡检计划
- 来源材料：session-codex-019d673f (Turn 13)
- 来源位置：检测周期讨论
- 状态：已确认

## decision_016：监控指标采用设备+指标+值格式

- 决策内容：监控指标展示采用"设备+指标+值"格式（如"储氧罐 O₂ 氧气浓度 20.6%"），合并原来的监测点列表和监控指标两个模块
- 决策原因：减少信息层级，让用户一目了然地看到完整的监测数据
- 替代方案：分开展示监测点列表和监控指标
- 为什么不选替代方案：信息层级过多，阅读效率低
- 影响范围：Dashboard
- 来源材料：session-codex-019d436a
- 来源位置：Dashboard监控指标讨论
- 状态：已确认
