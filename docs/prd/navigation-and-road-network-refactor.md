# PRD：导航体系重构与路网管理

## Problem Statement

当前系统按「管理端」和「实施端」两个独立平台组织菜单和路由，用户需要通过顶部 radio 切换才能访问不同功能，操作路径不直观。同时，点位管理页面的覆盖关系字段仅显示数量，无法直观了解具体覆盖了哪些装置、设施、部件和检测规则。此外，系统缺少路网管理功能，无法支持园区内自定义道路的规划与导航。

## Solution

1. **菜单扁平化**：去除管理端/实施端切换，将所有功能目录平铺为 8 个一级菜单，按业务逻辑自然排列。
2. **路网管理**：在「地图与空间」下新增路网管理模块，支持道路管理、节点绘制、连通性验证。
3. **点位覆盖信息增强**：点位管理页面的覆盖字段从数量改为名称展示，点位编辑页面的列名规范化。
4. **地图列表精简**：移除新建地图按钮和分区展开行，操作按钮文案统一。

## User Stories

1. 作为系统用户，我希望打开系统后直接看到所有功能菜单，不需要切换管理端/实施端，以便快速定位所需功能。
2. 作为系统用户，我希望菜单按「地图与空间 → 设施设备管理 → 检测规则 → 总调度台 → 规划与执行 → 异常中心 → 报表统计 → 系统配置」的顺序排列，以便按业务流程依次操作。
3. 作为系统用户，我希望在「地图与空间」菜单下看到「地图管理、点位管理、区域管理、路网管理」四个子项，以便统一管理空间相关信息。
4. 作为系统用户，我希望在「设施设备管理」菜单下看到「装置管理、设施设备、部件管理、机器人管理」四个子项，以便统一管理设备资产。
5. 作为系统用户，我希望在「检测规则」菜单下看到「检测规则配置、检测对象」两个子项，以便统一管理检测相关配置。
6. 作为系统用户，我希望在「系统配置」菜单下看到「设备管理、调度规则配置、资源基础配置、部件类型配置、通知配置、边巡边检」六个子项，以便统一管理系统级配置。
7. 作为系统用户，我希望默认进入总调度台页面作为首页，以便第一时间查看调度全局状态。
8. 作为系统用户，我希望在地图管理页面点击「路网」按钮直接跳转到该地图的路网管理页面，以便快速进入路网编辑。
9. 作为系统用户，我希望地图管理页面的操作按钮显示为「区域、点位、路网、编辑、删除」，名称简洁明了。
10. 作为系统用户，我不希望在地图管理页面看到新建地图按钮和分区展开行，界面更简洁。
11. 作为系统用户，我希望在路网管理页面左侧面板切换「道路管理、节点管理、连通性」三个 Tab，以便分别管理道路、节点和验证连通。
12. 作为系统用户，我希望在道路管理 Tab 中新增、编辑、删除道路，配置道路名称、类型（驾车/步行）、速度和颜色。
13. 作为系统用户，我希望在节点管理 Tab 中点击「绘制路线」按钮后，在地图上通过左键逐点添加节点、右键完成绘制，以便快速创建路线。
14. 作为系统用户，我希望在绘制路线时，系统自动连接相邻节点并生成路段，无需手动创建边。
15. 作为系统用户，我希望在节点管理 Tab 中点击「连接节点」按钮后，依次点击两个节点将它们连通，以便连接不同路线。
16. 作为系统用户，我希望点击地图上的节点后，在左侧面板查看和编辑节点信息，包括节点类型（普通节点/停车点/导航点）和导航名称。
17. 作为系统用户，我希望将节点类型设为「导航点」后，为该节点命名，只有命名的节点才支持导航。
18. 作为系统用户，我希望在连通性 Tab 中选择起点和终点节点，点击「检查连通性」后得到连通/不连通的结果，以便验证路网是否完整。
19. 作为系统用户，我希望路网管理页面支持从地图列表页传入 mapId 参数自动选中对应地图。
20. 作为系统用户，我希望路网管理页面的地图区域支持缩放和拖拽操作，以便查看路网细节。
21. 作为系统用户，我希望在点位管理页面的巡检 Tab 中，覆盖装置列显示装置名称（而非数量），以便直观了解该巡检点覆盖了哪些装置。
22. 作为系统用户，我希望在点位管理页面的巡检 Tab 中，覆盖设施列显示设施名称（而非数量），以便直观了解该巡检点覆盖了哪些设施。
23. 作为系统用户，我希望在点位管理页面的巡检 Tab 中，「覆盖部件」更名为「覆盖对象」，并显示部件名称（而非数量）。
24. 作为系统用户，我希望在点位管理页面的巡检 Tab 中，覆盖检测规则列显示规则名称（而非数量），以便直观了解绑定了哪些规则。
25. 作为系统用户，我希望覆盖名称列在超出 2 个时显示「+N」折叠，鼠标悬停查看完整列表，以免表格过宽。
26. 作为系统用户，我希望在巡检点配置页面（InspectionPointCreate）的配置表中，列名依次为「覆盖装置、覆盖设施设备、检测对象、检测规则、云台X轴、云台Y轴、焦距」，语义清晰。
27. 作为系统用户，我希望在巡检点详情页面（InspectionPointDetail）的配置详情表中，列名与配置页保持一致。
28. 作为系统用户，我希望点位编辑页面的「检测对象」列显示部件名称，「检测规则」列显示规则名称。

## Implementation Decisions

### 模块一：菜单与路由扁平化

- **修改 AppLayout.vue**：移除 `currentSystem` ref、header 中的 radio 切换按钮、所有 `v-if="currentSystem === ..."` 条件分支。
- **统一菜单结构**：将原来分散在管理端和实施端的菜单项合并为 8 个一级目录，使用统一的 `<a-menu>` 渲染。
- **菜单 key 体系**：为每个菜单项分配独立的 key（如 `map-list`、`device-list`），替代原来的 `management-xxx` / `implementation-xxx` 前缀。
- **openKeys 逻辑**：根据当前 `route.path` 前缀自动展开对应的一级菜单。
- **currentKey 逻辑**：通过 `route.path` 前缀匹配链确定当前高亮的菜单项。
- **路由路径保留**：短期内保留 `/management/*` 和 `/implementation/*` 路由路径不变，仅重组菜单显示，确保所有页面内跳转和浏览器书签不受影响。
- **默认首页**：`/` 重定向到 `/management/dispatch/center`（总调度台）。

### 模块二：路网管理

- **新增类型文件**：定义 `Road`（道路）、`RoadNode`（路网节点）、`RoadEdge`（路段）三个核心类型。
- **类型体系**：
  - `RoadType = 'driving' | 'walking'`
  - `RoadNodeType = 'normal' | 'parking' | 'navigation'`
- **数据存储**：扩展 `STORAGE_KEYS` 新增 `ROADS`、`ROAD_NODES`、`ROAD_EDGES` 三个 key。
- **MockService 扩展**：为每个路网实体提供完整的 CRUD 方法（get/save/delete + 按 mapId 过滤）。
- **页面结构**：左侧三 Tab 面板（道路管理/节点管理/连通性）+ 右侧 SVG 地图画布。
- **绘制交互**：左键逐点添加节点并自动连线，右键完成绘制。点击已有节点可连接到该节点。
- **连通性验证**：使用 BFS 算法检测两点之间是否存在连通路径。
- **地图交互**：支持鼠标滚轮缩放、拖拽平移。
- **URL 参数**：支持通过 `?mapId=xxx` 查询参数自动选中地图。

### 模块三：点位覆盖信息增强

- **PointManage.vue 巡检 Tab**：
  - `覆盖部件` 列更名为 `覆盖对象`。
  - 四个覆盖列从数量显示改为名称列表显示。
  - 新增 `getCoveredInstallationNames()`、`getCoveredFacilityNames()`、`getCoveredComponentNames()`、`getCoveredRuleNames()` 函数，返回 `string[]`。
  - 新增 `truncateNames(names, max)` 函数，超出 max 个名称时显示 `+N`。
  - 使用 `<a-tooltip>` 包裹，悬停显示完整名称列表。
  - 导入 `getDetectionItemConfigs` 用于解析检测规则名称。
- **InspectionPointCreate.vue**：配置表列名调整为「覆盖装置、覆盖设施设备、检测对象、检测规则、云台X轴、云台Y轴、焦距」，检测规则列移至云台参数前面。
- **InspectionPointDetail.vue**：详情表列名与配置页保持一致。

### 模块四：地图列表精简

- **移除新建地图按钮**：删除页面头部的「新建地图」按钮（含加号图标和 `#extra` 插槽）。
- **移除分区展开行**：删除 `expandedRowRender` 模板和相关 CSS。
- **操作按钮调整**：
  - `区域编辑` → `区域`
  - `点位编辑` → `点位`
  - 新增 `路网` 按钮，点击跳转 `/implementation/map/road-network?mapId=xxx`
  - 操作列宽度从 220px 调整为 280px
  - 新增 `goToRoadNetwork(mapId)` 函数

### 路由变更

- 在 `/implementation/map` 路由组下新增 `road-network` 子路由，懒加载 `RoadNetwork.vue`。

## Testing Decisions

本项目当前无测试框架配置（无 test script），本次变更未引入测试。以下为建议的测试方向：

1. **AppLayout 菜单渲染测试**：验证 8 个一级菜单按正确顺序渲染，无管理端/实施端切换元素。
2. **路网连通性验证测试**：构造节点图，验证 BFS 算法在连通/不连通场景下的正确性。
3. **覆盖名称解析测试**：构造 `coverageObjects` 和 `detectionConfigs` 数据，验证各 `getCoveredXxxNames()` 函数返回正确的名称数组。
4. **truncateNames 测试**：验证空数组、单元素、多元素截断等边界情况。

## Out of Scope

1. **路由路径迁移**：本次未将 `/management/*` 和 `/implementation/*` 路径迁移到新的顶级路径（如 `/map/*`、`/dispatch/*`），保留旧路径以确保兼容性。
2. **路网数据持久化**：路网数据仅存储在 localStorage，未对接后端 API。
3. **真实地图集成**：路网管理页面使用 SVG 画布模拟地图交互，未集成 MapLibre GL 或高德地图。
4. **导航路径规划**：连通性验证仅判断是否连通，未实现最短路径计算。
5. **驾驶舱（Cockpit）菜单项**：路由存在但未在菜单中展示，保持现状。
6. **报表统计子页面**：除已展示的 5 个报表页面外，其余报表子路由（任务执行分析、规划覆盖分析等）未在菜单中展示。

## Further Notes

- 路网管理的节点类型与巡检点位体系存在关联：`RoadNode.inspectionPointId` 可关联到 `InspectionPoint`，`nodeType === 'parking'` 对应停车点，`nodeType === 'navigation'` 对应巡检点。后续可深化这一关联。
- 路网的「道路绑定」功能已通过 `RoadEdge.roadId` 字段支持，但 UI 上的道路绑定交互（将绘制好的路段绑定到已有道路）尚未实现。
- 路网管理页面的 SVG 地图画布当前使用空白背景，后续可对接地图图片或瓦片服务。
